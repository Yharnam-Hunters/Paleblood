# Allocated SCE ELF image segments

The loader copies `PT_LOAD` and the separate SCE `PT_SCE_RELRO` segment (`0x61000010`) into the caller-owned writable image. It reports both through the existing `rt_elf_loads` layout, retaining their original flags and program-header order. This SCE segment is an allocation, unlike the standard GNU RELRO overlay. Overlap involving an SCE RELRO allocation is currently unsupported and rejected; the existing PT_LOAD-only copy order is unchanged.

Every admitted segment must fit the file, have `filesz <= memsz`, and have a nonwrapping image range. The mapper zeroes the whole image, copies file-backed bytes and then applies relocations, including relocations inside the new segment. The image extent includes all admitted ranges. It still requires a PT_LOAD. Existing relocation handling is unchanged.

Flags remain descriptive metadata. This change does not apply host memory protections or add a RELRO sealing step; callers must still provide a writable buffer for mapping. It does not implement module dependencies, constructors, dynamic loading, console syscalls, additional TLS forms or AppContent service behavior. The harness can now recognize this declared readable region, while a read-only flag does not add it to writable snapshots.

The retained AppContent and Ipmi files motivated the admission check. Their separate RELRO segments are disjoint from PT_LOAD and contain 216 and 1192 file bytes respectively. Their relocations cover every nonzero file byte, with the remaining 40 and 152 bytes zero, so existing zero-fill plus relocations can reconstruct those two ranges. No observed firmware startup failure is attributed to this omission. The owned regression instead includes nonzero, unrelocated SCE RELRO bytes, and checks exact copy, zero-fill, relocation order, flags, extent, canaries and malformed range rejection without executing ELF code.

Normal GCC 14 and Clang 19 Release builds passed the five Loader and nine Boot methods on standalone and full Linux compositions: 56 methods, zero skips. On macOS a native ARM64 mapper library passed all five mapping methods without executing ELF instructions; the normal whole-x86-64 Release runtime build passed the existing owned boot CTest. The initial Mac unittest invocation met a standard-library package-name collision before any mapper case; the corrected module path passed with unchanged sources and binaries. No original firmware or game code was executed.

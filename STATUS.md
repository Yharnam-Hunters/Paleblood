## Recent results

- Runtime: module loading at run time. `sceSysmoduleLoadModule` (libSceSysmodule, the only way the
  executable asks for a module) reports a module listed with action `stub` in `game/modules.csv`
  loaded without mapping it; `sceSysmoduleIsLoaded` and `sceSysmoduleUnloadModule` answer for it
  too. The ids are the public system module ids (OpenOrbis toolchain, after psdevwiki), recorded in
  the new `sysmodule` column; `tools/boot.py` passes them to `pbboot` as `--stub-module ID:NAME`, so
  `runtime/` still names no module, and `symbols/boot.json` gains `stub_modules` (which were
  loaded). Not yet re-run on the executable: the boot should still stop by name before the first
  load, with the executable's three libSceSysmodule imports now counted as implemented by the
  runtime.
- Module loading (`libSceSysmodule`): the error values (a module not loaded, an id the system does
  not know) and whether a second load of a loaded module is counted or refused are not public, so
  each stops the boot by name; so does a module that is not a stub, since the runtime cannot load a
  system module yet. Which ids the executable passes, and whether it reads more than success, is
  unobserved until the boot gets past direct memory (`docs/runtime-syscalls.md`, "Module loading at
  run time").

- `BB_TARGET_FPS` (30, 60, uncapped) does what the community frame-rate patches "30 FPS++",
  "60 FPS++" and "Uncap FPS++" do, in every replaced function they edit, and each part is
  checked against the patch itself (`tools/verify.py run --patch FILE:NAME --env ...`,
  [VERIFY.md](docs/VERIFY.md)). Measured on a real screen (2026-10-07, 2560x1440 at 165 Hz, all
  replacements hooked, `BB_TARGET_FPS=60` with "60 FPS++"): frame pacing median 16.67 ms, p99
  16.69 ms, no frame over 1.5x the median.
- The runtime fork now starts native: no upscaler, no jitter, full screen at the display's size.
  With its temporal upscaler (FSR 3, jitter on), the sky showed the lower half of the screen
  mirrored into it; at native it does not.
- Unattended runs reach gameplay: `tools/play_route.py` plays `game/routes/*.route` (pad
  presses, keyboard text, waits on on-screen text): `new_game.route` goes from the title through
  character creation to the contract (which saves), `continue.route` loads that save into
  Iosefka's Clinic.
- Call counting probes (`BB_PROBES`, `runtime/probe.c`) show which original functions a run
  reaches; `tools/patch_overlap.py` and `tools/reloc_refs.py` map patches to functions and find
  callers through relocated pointers.
- Nine fixed-step state methods of a Chalice Dungeon state machine are replaced and checked on
  edge cases; they need a save that reaches the Chalice Dungeons to be recorded in-game.
- [QUIRKS.md](QUIRKS.md): Ghidra hides the code after calls to the engine's fatal error.
- The frame-rate patches also rewrite shared constants in the data segment (for example the
  1/30 s step at `0x04d29170`), which unreplaced code reads too. `BB_TARGET_FPS` is meant to run
  together with the patch for the rest of the game, so `verify.py run --patch` now applies the
  patch to both sides.

## Known issues

- Recording every hooked function at once slows frames enough to crash the runtime in the
  opening cutscene (a guest fault or a bad GPU command packet). With recording off, all
  replacements run clean; runs record only the functions they need (`BB_CAPTURE_ONLY`).
- An intermittent GPU library assertion (bad PM4 packet) while a save loads, about 75 s into a
  run, with or without recent hooks; the next run is clean.
- Rare NVIDIA Xid 32 errors at Vulkan device creation; the run aborts before game code runs.

## Open questions (runtime)

- The CPU affinity mask of the main thread on a PS4 is still not measured. Since the maintainer's
  2026-11-11 ruling, a thread with no mask set by the guest answers `0x3f`, six CPUs
  (`scePthreadGetaffinity`, `scePthreadAttrGetaffinity`), replacing the earlier all ones. The
  bundled C library's thread-count probe that asks for it is no longer hooked out (#207's hook was
  dropped), so it now counts that ruled mask: 6 CPUs, not a measured value.
  `std::thread::hardware_concurrency`, its only reader found, still stops by name.
